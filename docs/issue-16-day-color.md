# Issue #16：白天圆球颜色去灰

2026-10-21，承接 `codex/issue-16-pressure-reset` 的 `9a9480e`。用户确认按压质感、回弹与换色同步动画，要求仅改善白天球体颜色发灰。

## 改动与边界

在 `src/orb-preview.js` 上传球体顶点颜色时，仅白天将线性 RGB 相对亮度的色差放大至 1.30 倍，再乘 1.06 并限制至有效范围；之后沿用原有压痕遮蔽。初次加载及昼夜切换都会更新颜色。夜晚不加此补偿，基础色卡和换色时钟保持原值。

不改已确认的阻力、残留压痕、回弹、旋转、换色时长与覆盖方向，不改灯光、网格、材质粗糙度或布局。无需新增模型或纹理。GLB 仍为 124,324 字节，2562 顶点 / 5120 三角形；构建脚本为 640,065 字节。着色循环只在形变、换色或主题变化时更新，静止后停帧。

## 实际验证

- `npm test`（包含构建）：73/73 通过，0 失败/跳过，退出 0。结果见 [完整测试日志](../artifacts/issue-16-day-color/tests.txt)。新增四项真实 GPU 测试覆盖十色、首帧、昼夜往返、压痕、姿态、换色动画与停帧。
- `node capture-orb-day-color.cjs`：以 `9a9480e` 的实际构建作为之前版本，同浏览器/页面/模型逐色对比。十色白天全部产生可见颜色变化，十色夜晚像素差均为零；无页面异常、无横向溢出。详见 [机器记录](../artifacts/issue-16-day-color/validation.json)。
- Windows 11（10.0.26200 x64）、Chromium 155.0.4283.62。桌面 1440×900、手机 390×844、小手机 320×568、横屏 844×390，均保存昼夜静止及按压截图。手机为浏览器模拟，无真实手机测试；不报告未经测量的帧率。
- 之前提交的远端检查暴露出减少动态模式 120ms 动画测试对“必须呈现小于半深的中间帧”的不合理假设。慢 GPU 可以跳过该深度。本次改为检查实际呈现帧中形变和颜色同时变化，并保留首帧不突变、单调恢复、最终姿态/形态与停帧断言；不为测试改变产品动画。

## 风险与回滚

不同屏幕与浏览器色彩管理可能仍有观感差异，需真机复核。补偿不是完整光学材质模拟，奶油白保持低饱和。回滚本次颜色提交可恢复旧白天颜色，并保留此前已确认的按压与同步动画。后续碎裂前仍需独立设计外壳/软芯及破裂网格，并完成真机输入、性能与触感验收；本轮不制作裂纹、碎片或声音，Issue #16 保持开放。
